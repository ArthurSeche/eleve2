Exercices 3 — E-commerce GA4

Vous allez mesurer tout le parcours d'achat de la boutique Kop Store, de la fiche produit jusqu'à la confirmation de commande. Puis vous apprendrez à lire vous-même le dataLayer, avant une mission à mener en autonomie.

Comment fonctionne la boutique. Le site n'envoie rien au dataLayer. À chaque action du client, il appelle une fonction « crochet » que vous écrivez dans le fichier mes-tags.js, chargé sur toutes les pages. Par exemple, quand une fiche produit s'affiche, la boutique appelle shopHooks.viewItem et lui donne les informations du produit dans data.

Vos trois outils :

  • Le bouton { } dataLayer, en bas à gauche de chaque page : il montre en direct tout ce qui est poussé.
  • La console du navigateur (F12, onglet Console) : un console.log(data) dans un crochet affiche ce que la boutique vous donne. Une ligne rouge signale une erreur dans votre code.
  • Le lien « Réinitialiser la boutique », en pied de page : il vide le panier et la commande pour repartir de zéro.
Dans GTM, une fois pour toutes : un déclencheur Événement personnalisé avec l'expression régulière ci-dessous (case « Utiliser la correspondance d'expression régulière » cochée), et une balise Événement GA4 dont le nom d'événement est {{Event}}, avec « Envoyer les données d'e-commerce » coché (source : Couche de données). Tous les événements du tunnel passeront par elle. 
^(view_item_list|select_item|view_item|add_to_cart|add_to_wishlist|view_cart|remove_from_cart|begin_checkout|add_shipping_info|add_payment_info|purchase)$
Si plus rien ne remonte : ouvrez la console (F12). Une seule erreur dans mes-tags.js bloque tout le fichier. Pensez aussi à désactiver votre bloqueur de publicité sur ce site, et à recharger avec Ctrl + F5.
Partie A · guidée

Le tunnel d'achat

1. Le dictionnaire Fondation

Pourquoi : la boutique et GA4 ne parlent pas la même langue. Le développeur a nommé ses champs comme il voulait (sku, name…) ; Google impose les siens (item_id, item_name…). Votre premier travail d'analyste est de traduire.

  1. Dans mes-tags.js, écrivez shopHooks.viewItem = function (data) { console.log(data.product); };, ouvrez une fiche produit et regardez la console.
  2. Complétez le dictionnaire :
La boutique ditGA4 attendExemple
skuitem_idSRFC-DOM-26
nameitem_nameMaillot Domicile Stade Rennais
branditem_brandPuma
categoryitem_categoryMaillots

  1. Écrivez la fonction traductrice versItem, en haut de mes-tags.js. Elle servira dans tous les exercices suivants.
Afficher le code

🟢 Code à coller dans mes-tags.js

/* Le dictionnaire : vocabulaire de la boutique → vocabulaire GA4 */
function versItem(x) {
  return {
    item_id: x.sku,
    item_name: x.name,
    item_brand: x.brand,
    item_category: x.category,
    item_variant: x.size,       // vide quand on regarde un produit sans taille choisie
    price: x.price,
    quantity: x.quantity || 1   // 1 par défaut
  };
}

2. Vue d'un produit — view_item ★

Pourquoi : c'est l'entrée du tunnel. Sans elle, impossible de calculer le taux d'ajout au panier (ajouts ÷ vues), l'indicateur n°1 d'une fiche produit.

À faire : écrire shopHooks.viewItem pour pousser view_item, en utilisant versItem(data.product).

Réussi quand : sur le maillot, item_id = SRFC-DOM-26 et value = 90 ; sur l'écharpe, KOP-ECH-01 et 22.

Afficher le code

🟢 Code à coller dans mes-tags.js

shopHooks.viewItem = function (data) {
  dataLayer.push({ ecommerce: null });
  dataLayer.push({
    event: "view_item",
    ecommerce: {
      currency: "EUR",
      value: data.product.price,
      items: [versItem(data.product)]
    }
  });
};

3. Ajout au panier — add_to_cart ★★

Pourquoi : mesurer un ajout réussi, et non un simple clic. Cliquez sur « Ajouter au panier » sans choisir de taille : rien n'est ajouté. Un tracking au clic aurait compté un faux ajout.

À faire : écrire shopHooks.addToCart. La boutique donne le produit dans data.product, et à part la taille (data.size), le prix unitaire flocage compris (data.unitPrice) et la quantité (data.quantity).

Réussi quand : taille L, quantité 3 → item_variant: "L", quantity: 3, value: 270. Avec flocage, price passe à 105.

Afficher le code

🟢 Code à coller dans mes-tags.js

shopHooks.addToCart = function (data) {
  var item = versItem(data.product);
  item.item_variant = data.size;      // la taille choisie
  item.price = data.unitPrice;        // le prix, flocage compris
  item.quantity = data.quantity;      // la quantité ajoutée
  dataLayer.push({ ecommerce: null });
  dataLayer.push({
    event: "add_to_cart",
    ecommerce: {
      currency: "EUR",
      value: data.value,
      items: [item]
    }
  });
};

4. Début de commande — begin_checkout ★★

Pourquoi : sans cette étape, on voit des ajouts au panier puis des achats, mais rien entre les deux. Elle coupe le tunnel en deux : abandon dans le panier, ou pendant la commande ?

À faire : la boutique appelle shopHooks.beginCheckout à l'arrivée sur la page commande. Les articles sont dans data.lines et les montants dans data.totals. Astuce : data.lines.map(versItem) traduit chaque article de la liste.

Réussi quand : maillot M seul → value: 90, 1 article. Avec le code GTM10 saisi dans le panier → value: 81 et coupon: "GTM10".

Afficher le code

🟢 Code à coller dans mes-tags.js

shopHooks.beginCheckout = function (data) {
  dataLayer.push({ ecommerce: null });
  dataLayer.push({
    event: "begin_checkout",
    ecommerce: {
      currency: "EUR",
      value: data.totals.subtotal - data.totals.discount,
      coupon: data.totals.coupon || undefined,
      items: data.lines.map(versItem)
    }
  });
};

5. Livraison et paiement ★★

Pourquoi : savoir où les clients abandonnent pendant la commande. Après avoir vu les frais de port ? Au moment de payer ?

À faire : deux crochets presque identiques à begin_checkout, avec une information en plus chacun :

6. L'achat — purchase ★★★

Pourquoi : c'est l'événement qui porte le chiffre d'affaires. Un achat compté deux fois, c'est un faux chiffre présenté à la direction.

À faire : la boutique appelle shopHooks.purchase sur la page de confirmation. La commande est dans data.order (numéro, montants, articles dans data.order.lines).

  • Envoyez transaction_id, value, tax, shipping, coupon et les articles.
  • Rechargez la confirmation : l'achat ne doit pas repartir. Indice : data.firstView.
  • Décidez si value inclut les frais de port, et justifiez votre choix.
Afficher le code

🟢 Code à coller dans mes-tags.js

shopHooks.purchase = function (data) {
  if (!data.firstView) return; // page rechargée : on n'envoie pas l'achat une 2e fois
  var o = data.order;
  dataLayer.push({ ecommerce: null });
  dataLayer.push({
    event: "purchase",
    ecommerce: {
      transaction_id: o.transaction_id,
      currency: o.currency,
      value: Math.round((o.total - o.shipping) * 100) / 100,
      tax: o.tax,
      shipping: o.shipping,
      coupon: o.coupon || undefined,
      items: o.lines.map(versItem)
    }
  });
};
Partie B · guidée

Les variables de couche de données

Le dataLayer est une mémoire. Une variable de couche de données (DLV) est une étiquette GTM qui va chercher une information précise dans cette mémoire, pour l'utiliser dans une balise ou un déclencheur. Jusqu'ici, la case « Envoyer les données d'e-commerce » faisait ce travail pour vous ; maintenant, vous le faites à la main.

7. Le code promo — lire une valeur ★★

Pourquoi : savoir quels codes les clients tapent, y compris les faux. Si 200 personnes tapent « NOEL50 », un faux code circule sur internet.

  1. Écrivez shopHooks.couponApplied pour pousser un événement inventé coupon_applied, avec coupon_code et coupon_valid (« oui » ou « non »).
  2. GTM : deux variables de couche de données, DLV - coupon_code et DLV - coupon_valid.
  3. GTM : un déclencheur Événement personnalisé coupon_applied et une balise Événement GA4 coupon_applied avec les deux paramètres.
  4. GA4 : Administration → Définitions personnalisées → deux dimensions personnalisées, champ d'application Événement, paramètres coupon_code et coupon_valid.

Réussi quand : dans le panier, NOEL50 donne coupon_valid: "non" et GTM10 donne "oui" (onglet Variables de Tag Assistant).

Afficher le code

🟢 Code à coller dans mes-tags.js

shopHooks.couponApplied = function (data) {
  dataLayer.push({
    event: "coupon_applied",
    coupon_code: data.coupon,
    coupon_valid: data.valid ? "oui" : "non"
  });
};

8. La commande premium — une variable comme condition ★★★

Pourquoi : repérer les grosses commandes (100 € et plus). Aucun code à écrire : vous lisez une valeur que votre purchase envoie déjà.

  1. GTM : variable de couche de données DLV - montant commande, nom ecommerce.value. Le point permet d'aller chercher value à l'intérieur de ecommerce.
  2. GTM : déclencheur Événement personnalisé purchase, « Certains événements personnalisés », condition DLV - montant commande supérieur ou égal à 100.
  3. GTM : balise Événement GA4 commande_premium, sans paramètre, sur ce déclencheur.

Réussi quand : 1 maillot (90 €) → la balise ne part pas. 2 maillots (180 €) → elle part.
Question : 1 maillot + livraison express = 99,90 €. La balise part-elle ? Pourquoi ?

Coups de pouce

Chaque coup de pouce ouvert coûte un point. Ouvrez-les seulement si vous êtes bloqués.

Coup de pouce 1 — Par où commencer ?

L'annexe liste tous les crochets de la boutique. Trouvez ceux qui correspondent aux trois questions, puis commencez chacun par un console.log(data) pour voir ce que la boutique vous donne.

Coup de pouce 2 — Quels noms d'événements ?

Pour deux des trois questions, Google a déjà prévu un nom officiel. Cherchez « GA4 recommended events » sur internet. Un nom officiel débloque des rapports tout prêts dans GA4 ; un nom inventé oblige à tout reconstruire à la main.

Coup de pouce 3 — Ai-je le droit de tout envoyer ?

Relisez la question 2. Le crochet de la newsletter vous donne quelque chose que vous n'avez pas le droit d'envoyer à Google Analytics. Lequel, et pourquoi ?
