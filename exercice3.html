Exercices 3 — E-commerce GA4

La boutique Kop Store fonctionne comme un vrai site marchand : fiche produit, panier, code promo, tunnel de commande, confirmation. À vous de remonter chaque étape dans GA4.

Le lien « Achetez ce produit » de la fiche produit mène directement à la confirmation (achat express). Le bouton { } dataLayer en bas à gauche de chaque page affiche en direct le contenu du dataLayer. Le lien « Réinitialiser la boutique » en pied de page vide panier, favoris et commande.

Deux méthodes, un objectif

Méthode A — GTM seul : un déclencheur « Clic » sur le bon bouton, des variables « Élément DOM » qui lisent les attributs data-* de la page (par exemple data-sku, data-price sur #product). Rapide, sans toucher au code… mais fragile.

Méthode B — dataLayer.push : le site envoie lui-même l'événement au bon moment, avec les bonnes données. C'est la méthode recommandée par Google pour l'e-commerce. Ici, vous jouez le rôle du développeur : vous écrivez vos dataLayer.push dans le fichier mes-tags.js (chargé sur toutes les pages).

La boutique n'envoie rien au dataLayer. En revanche, à chaque action, elle appelle une fonction « crochet » que vous pouvez écrire :

// dans mes-tags.js
shopHooks.addToCart = function (data) {
  console.log(data);          // 1. regardez d'abord ce que contient data
  dataLayer.push({ ecommerce: null });
  dataLayer.push({
    event: "add_to_cart",
    ecommerce: { /* 2. à vous de construire l'objet GA4 */ }
  });
};
Côté GTM, pour tous les événements e-commerce : un déclencheur Événement personnalisé (nom exact de l'événement), une balise Google Analytics : événement GA4, et dans « Plus de paramètres », cochez Envoyer les données d'e-commerce avec la source Couche de données. GA4 lit alors tout seul l'objet ecommerce.

Échauffement Rappel

Vous savez déjà envoyer un purchase quand on clique sur « Achetez ce produit ». Avant d'aller plus loin, listez tout ce qui cloche avec cette méthode :

  • Quel transaction_id envoyez-vous ? Est-il unique ?
  • Que se passe-t-il si l'élève clique deux fois, ou fait « retour » puis reclique ?
  • Et si l'achat se fait par le panier et le tunnel de commande, sans passer par ce lien ?

Les exercices 7 et 8 règlent ces problèmes.

Exercice 1 — Vue d'un produit ★ Débutant

Envoyez view_item à GA4 à chaque affichage d'une fiche produit.

  1. Ouvrez mes-tags.js, décommentez le modèle shopHooks.viewItem et complétez les paramètres manquants.
  2. Dans GTM : déclencheur Événement personnalisé view_item + balise événement GA4 avec les données e-commerce.
  3. Testez avec le mode Aperçu sur le maillot domicile, puis sur l'écharpe.

Attendu : view_item avec currency, value et un items contenant item_id, item_name, item_brand, item_category, price, quantity.

Exercice 2 — Clic « Ajouter au panier » avec GTM seul ★★ Intermédiaire

Sans écrire de dataLayer.push, envoyez un événement add_to_cart au clic sur le bouton Ajouter au panier.

  1. Déclencheur Clic – Tous les éléments sur le bouton (son id est add-to-cart, sa classe btn-add-to-cart).
  2. Variables Élément DOM qui lisent data-sku, data-name, data-price sur l'élément #product.
  3. Variable Variable d'événement automatique → attribut data-selected-size de l'élément cliqué.
  4. Une variable JavaScript personnalisé qui renvoie le tableau items :
function () {
  return [{
    item_id: {{DOM - sku}},
    item_name: {{DOM - nom}},
    price: Number({{DOM - prix}}),
    item_variant: {{Clic - taille}},
    quantity: Number(document.getElementById("qty-input").value)
  }];
}
Le piège : cliquez sur « Ajouter au panier » sans choisir de taille. Le produit n'est pas ajouté… mais votre balise s'est-elle déclenchée ? Notez ce que vous observez : c'est tout l'intérêt de l'exercice suivant.

Exercice 3 — Ajout au panier via dataLayer ★★ Intermédiaire

Écrivez shopHooks.addToCart pour pousser un vrai add_to_cart, uniquement quand l'ajout a réussi. Mettez en pause la balise de l'exercice 2.

  • Sans taille choisie : aucun événement.
  • Taille L, quantité 3 : quantity: 3, item_variant: "L", value: 270.
  • Avec flocage : le price unitaire passe à 105.
  • Le bouton « + » de la page panier déclenche aussi un add_to_cart (quantité 1). Normal ?

Exercice 4 — Favoris et guide des tailles ★ Débutant

Sur la fiche produit :

  • Le cœur ♡ envoie add_to_wishlist (événement e-commerce recommandé par GA4).
  • Le lien « Guide des tailles » envoie un événement personnalisé size_guide_open avec un paramètre product_id. Pensez à déclarer la dimension personnalisée dans GA4 !
  • Bonus : un événement select_size avec la taille choisie. Est-ce vraiment utile d'envoyer ça à GA4 ?

Exercice 5 — Listes de produits ★★ Intermédiaire

Mesurez quelles listes font cliquer : la boutique, les meilleures ventes de l'accueil et le bloc « Vous aimerez aussi » de la fiche produit.

  • view_item_list avec item_list_id, item_list_name et un index pour chaque produit.
  • select_item au clic sur une carte, avec la position du produit cliqué.
Bonus GTM : le bloc « Vous aimerez aussi » est en bas de page, beaucoup de visiteurs ne le voient jamais. Utilisez plutôt un déclencheur Visibilité de l'élément sur #related-products (50 % visible, une fois par page) pour n'envoyer view_item_list que lorsqu'il est réellement vu.

Exercice 6 — Le panier ★★ Intermédiaire

Ajoutez 2 ou 3 articles puis ouvrez le panier.

  • view_cart au chargement, avec tous les articles et la valeur du panier.
  • remove_from_cart sur « Supprimer » (toute la quantité) et sur « − » (quantité 1).
  • Un événement personnalisé coupon_applied quand un code est saisi (testez GTM10 et un faux code). Envoyez-vous les codes invalides ?

Exercice 7 — Le tunnel de commande ★★★ Avancé

Depuis le panier, cliquez sur « Passer la commande ».

  • begin_checkout au chargement de la page commande (avec coupon s'il y en a un).
  • add_shipping_info au clic sur « Continuer vers le paiement », avec shipping_tier (Standard, Point relais ou Express).
  • add_payment_info au clic sur « Payer », avec payment_type.

Question : dans GA4, le rapport « Parcours d'achat » utilise ces événements. Que se passe-t-il si begin_checkout manque ?

Exercice 8 — L'achat, le vrai ★★★ Avancé

Sur la page de confirmation, envoyez un purchase complet.

  • transaction_id (ex. KOP-20260930-1234), value, tax, shipping, currency, coupon.
  • items avec la taille de chaque article en item_variant.
  • Rechargez la page : la transaction ne doit pas être renvoyée. Indice : regardez data.firstView.
  • Décidez si value inclut ou non les frais de port, et justifiez votre choix.
  • Faites un achat par le tunnel et un achat express (« Achetez ce produit ») : les deux doivent remonter.

Vérifiez dans GA4 → DebugView, puis le lendemain dans Rapports → Monétisation → Achats e-commerce.

Bonus ★★

  • Newsletter du pied de page : envoyez generate_lead. Pourquoi ne faut-il surtout pas envoyer l'adresse e-mail à GA4 ?
  • Créez un seul déclencheur pour tous les événements e-commerce grâce à une expression régulière, et une seule balise GA4 dont le nom d'événement est {{Event}}.
  • Ajoutez un paramètre page_type (home, product, cart…) à tous vos événements. Indice : regardez l'attribut data-page de la balise <body>.
